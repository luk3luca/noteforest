All removals are from `tests/e2e/m2-editor.test.mjs`.

| Removed | Replacement evidence |
|---|---|

| `overwrites an external modification only after a Cancel-default confirmation` | Unit `save-failure.test.ts` — `overwrites through the save IPC after external modification and clears the failure` and `names the path and defaults the overwrite confirmation to Cancel`; unit `storage.test.ts` — `refuses to overwrite externally changed bytes unless forced` (the next save after overwrite must not re-report a conflict); on-demand visual `m2-screenshots.test.mjs` — `captures the external-modification banner and overwrite confirmation` (real banner, dialog, Cancel). |
| `saves a copy after external modification without touching the external file` | `saves a copy of the unsaved content and leaves the original untouched` — same save-copy action, save dialog IPC, tab activation, block-identity and original-bytes assertions; unit `save-failure.test.ts` — `offers overwrite only for external modification` (the failure code only selects the banner that triggers the same action). |
| `dismisses a failed-save quit through the E2E dialog guard` | Unit `dialog-guard.test.ts` (3 tests: default cancel, explicit `cancelId`, save/open dialogs); the guard is installed for every e2e run and the recovery suite asserts `__nfDialogCalls` stays empty (`m2f-recovery.test.mjs` — `quits a read-only stale-lock document without a dialog or a package write`); the explicit quit failure path remains in `surfaces a flush error on quit and keeps the app open until Cancel`. |
| `blocks closing on a failed save and keeps the content until Retry succeeds` | `surfaces a permission save failure and recovers with Retry` (banner, action set, retry, content saved); `keeps the window open on a flush timeout and closes after Retry` (close blocked, Retry closes); `saves pending edits on close and restores them after relaunch` (content after relaunch); unit `flush.test.ts` — `blocks when an editable document is in a failed-save state`. |

**Candidates evaluated and kept**

- `saves pending edits on close...` / `...on quit...` — close and quit are distinct lifecycle
  entries (`close` event vs `before-quit`); not proven redundant.
- `keeps the window open on a flush timeout...` / `surfaces a flush error on quit...` — different
  flush results (`timeout` vs `error`), different lifecycle entries, and different user responses
  (Retry closes vs Cancel keeps the app open). Unit `lifecycle.test.ts` covers both decisions,
  but neither e2e is a duplicate of the other.
- Text-anchor create/undo/reload — the only app-level path for anchored branches.

**Required keep list still present:** create/edit/branch/reopen (test 1), close/quit flush (tests
8–11), save failure/retry (13), external modification + reload (15), save copy (14), last-window
quit (12), text-anchor flow (16).

## Formula-term edit fixture (S3-7 / AC-57)

- `scripts/generate-fixtures.mjs` now generates `fixtures/m3-formula-term-edit.json`:
  - parent `m3fe-formula` with a `mathBlock` `a^2 + b^2 = c^2` carrying anchor
    `m3fe-a-term` (`form: term`, `latex: 'a^2 + b^2'`, `occurrenceHint: 1`);
  - child `m3fe-term-child` and primary branch `m3fe-e-term`;
  - one chapter; the fixture validates with no warnings and is included in the fixture matrix
    (`covers: ['formula term edit']`).
- New table case in `packages/core/test/fixtures.test.ts`
  (`re-resolves a term after edits around it and keeps the anchor, branch, and target`):
  1. initial `a^2 + b^2 = c^2` → resolved, exact binding, atomic, 1 candidate;
  2. edited around the term `x = 4(a^2 + b^2) - 1` → resolved, exact binding, 1 candidate;
  3. repeated term `a^2 + b^2 + a^2 + b^2` → ambiguous, `multiple-candidates`, 2 candidates;
  4. term removed `x^2 + y^2 = z^2` → broken, `quote-missing`, 0 candidates;
  5. term restored `a^2 + b^2 = c^2` → resolved again.
  Each edit goes through the real `block.editContent` command; every state asserts the anchor
  record, branch record, and target block are deep-equal to the initial records.
- No UI or product change; image rows of AC-57 remain deferred to M3c3b.

## Risks

- **Overwrite confirmation is no longer in the critical gate.** Its app-level evidence is the
  on-demand visual suite; unit tests cover the overwrite IPC, the default-Cancel copy, and the
  post-overwrite baseline. Recorded in the matrix's known gaps; restore a critical overwrite path
  if the visual suite is retired.
- **Recovery/E2E runtime variance.** The critical suite varies with machine load; the removed
  tests were cheap (~1–2 s each), so the wall-time gain is modest (the maintenance-surface gain is
  the point). The 60 s budget still has ~16 s headroom.
- **No product behavior changed.** Only test support, fixtures, and architecture docs changed.
- **Fixture regeneration.** `npm run fixtures` is deterministic on this machine: only the new
  `m3-formula-term-edit.json` was added; the 13 existing fixtures were byte-identical.
