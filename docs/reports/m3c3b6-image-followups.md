## AVIF dimensions (S3-1)

`readIsoBox` reads a box header defensively:

- big-endian 32-bit size + 4-character type;
- `size === 1` reads the 64-bit `largesize` form (high word must be 0);
- `size === 0` means “to the end of the enclosing container”;
- a truncated, zero-length, or out-of-range box returns `null` (fail closed).

`avifDimensions` then walks boxes recursively:

- `meta` is a full box, so its children start after the 4-byte version/flags;
- `iprp` and `ipco` are plain containers;
- `ispe` is a full box: version/flags (4), width (4), height (4);
- `iref` and any other box are skipped;
- recursion stops after `AVIF_MAX_BOX_DEPTH = 6` container levels;
- the first positive `ispe` wins; a zero/missing dimension returns `null`;
- the walker never throws and never reads past the declared box end.

The previous top-level `ispe` behavior still works (covered by a synthetic test).

## Stale placeholder attr cleanup (S4-1)

Rule:

- `contentWithImageAsset` deletes `unavailable` and `clipboardAssetId` before
  assigning the new `assetId`; alt text and dimensions are still updated as
  before.
- `canonicalImageAttrs` always deletes `clipboardAssetId` (it is editor-only),
  deletes empty/null `assetId`, and deletes `unavailable` whenever a non-empty
  `assetId` is present. It still drops `src`, `title`, `missing`, `missingLabel`,
  `missingReason`, and `clipboardUnavailable`.
- A failed cross-document copy is unchanged: no `assetId`, a durable
  `unavailable: "cross-document-copy"` marker, alt text preserved.

Test: a placeholder with `unavailable`, `clipboardAssetId`, alt, and dimensions
is replaced; the canonical node has only `assetId`/alt/dimensions, and a reload
projection produces the asset URL with `missing: false`.

## Availability gate (S4-2)

`imageAnchorAuthoringGate` in `lib/image.ts` is the single gate:

| Input | Result |
|---|---|
| not editable | disabled, `read-only` |
| empty `assetId` or no record | disabled, `asset-record-missing` |
| `assetAvailability[assetId] === 'asset-changed'` | disabled, `asset-changed` |
| any other non-`available` state | disabled, `asset-missing` |
| `undefined` (unchecked) or `'available'` | allowed |

The index keeps only non-available states (`AssetAvailabilityIndex` semantics), so
`undefined` means “not observed as unavailable”, matching the projection and
anchor resolver. No second availability store was added.

Menu labels:

- `Add image region… — image asset missing`
- `Add image region… — image file missing`
- `Add image region… — image asset changed`
- `Add image region… — document is read-only`

The same `imageActionEntries` function serves the block menu and the per-image
inline menu. `beginImageAnchorAuthoring` re-checks the gate as defense in depth,
so a programmatic call cannot start authoring for a missing/changed asset.
Replace stays gated only by editability; alt editing is unchanged.

The broken-image placeholder now renders a single “Image actions…” button in an
editable document. It has no draw layer, so Add region/point are disabled with
the reason, while Replace/alt remain safe repair actions. Screenshots:
`artifacts/m3c3b3/image-file-missing-actions-1440x900.png` and
`artifacts/m3c3b3/image-hash-changed-actions-1440x900.png`.

## Risks

1. **First `ispe` wins.** The walker does not parse `ipma` item/property
   associations. A multi-item AVIF (for example an auxiliary alpha item with its
   own `ispe`) could report the first property box rather than the primary
   item's. Ordinary single-image AVIF and the checked-in fixture are correct.
2. **Session-scoped availability.** The gate reads the open session's
   `assetAvailability`, which is populated at open and on asset commands. A file
   deleted/replaced while the document is open stays trusted until reload (the
   existing ratified policy); authoring can then start and fail at branch time.
3. **Placeholder inline menu is new UI.** It is limited to editable documents
   and one button, but the visual/VoiceOver judgement belongs to the product
   owner. The 224 px context menu wraps the long disabled label onto two lines.
4. **Unknown future availability states** are treated as `asset-missing`
   (fail closed) until the gate is taught otherwise.
5. **AVIF fixture reproducibility.** It is a macOS `sips` artifact, not
   regenerated by the fixture script; a future fixture regeneration must not
   delete it silently.
