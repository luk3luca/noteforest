Deletion test, applied per candidate: 1 and 2 concentrate (delete them and the listings /

5 and 6 pass the test but each site is small today (hence Speculative).

## Top recommendation

**Candidate 1 — deepen the command surface.** It sits on the four hottest files in the repo
(`App.tsx`, `actions.ts`, `state/shell.ts`, `shell/Sidebar.tsx`), so every future UI batch pays
the multi-listing tax; it converts the most UI-suite-covered behavior (availability under Read
mode, guest files, and no-document states) into one interface testable without Electron; and it
needs no product decision and no ADR. Candidate 2 is the strongest follow-up: it completes a
ratified contract, but it wants a performance gate and an owner-visible review pass first
(candidate 2's alignment may change which callouts render as ambiguous — the ADR-required
behavior, but visible).

## ADR checks

- No candidate contradicts a ratified ADR. Candidate 2 **completes** ADR-0005 ("one resolver …
  index per block, cache by content hash, invalidate only edited blocks"), which is currently
  only partially implemented. Candidate 4 keeps ADR-0002's separate print skin. Candidates 3, 5,
  and 6 touch no ADR territory.
- ADR-0003 (external agent API) stays withdrawn; nothing here reopens a server/command-inbox
  surface.

## Product decisions needed

None blocking. Two owner-review items, not decisions:

1. Candidate 2: after alignment, a callout previously drawn as resolved (hint-picked rect) may
   display ambiguous. ADR-0005 already forbids auto-resolution, so this is sanctioned behavior,
   but the change is visible on the canvas.
2. Candidate 5: the capability reasons must reuse the existing palette/menu wording verbatim;
   any new user-visible copy needs the usual UX review.

## What I could not verify

- I did not build the app or run any suite (`npm test`, e2e, UI, `test:perf`). The survey is
  read-only on a frozen baseline; the churn evidence is from `git log`, the friction claims from
  reading.
- Anchor-resolution cost is inferred from the code (repeated resolution per surface, no shared
  cache), not measured. Whether it is perceptible at 300–1,000 blocks needs `npm run test:perf`
  before and after.
- Whether core's resolver and the layout package's state derivation visibly disagree in a real
  document: the rules differ (selector fallback vs measured marks), and constructing a live
  repro needs a crafted fixture.
- The 29 guest-file check sites were found by search and sampled, not audited one by one.
- The HTML report relies on Tailwind and Mermaid CDNs at view time; offline it renders partially
  (hand-built SVG diagrams survive, Mermaid graphs degrade to text).
